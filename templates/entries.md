# 条目模板

> 往已有文件里加的「一条」怎么写。整份文件的模板见 [INDEX](INDEX.md)。
> 通用约定：日期 `YYYY-MM-DD`；推断标「（推断）」；不确定的标 `?`；自动写入的标「（自动）」；链接用相对路径。

## journal
```markdown
## HH:MM <一句话标题：做了什么 / 发生了什么>
#project/<slug> #area/<slug> #<其他标签>

<具体：做了什么、结果如何、卡在哪。省略主语。>

- 结果/产出：<文件、PR、结论>
- 待办：
  - [ ] <下一步>
```
- 补记过去的日子：写进对应日期的文件，标题后加 `(补记 YYYY-MM-DD)`
- 当天最后一条可以是 `## HH:MM 今日小结`（一两句）

## 时间线
项目或领域档案的「时间线」小节，按时间顺序追加：
```markdown
- YYYY-MM-DD — <一句话：发生了什么> · [journal](../../journal/YYYY/MM/YYYY-MM-DD.md)
```
自动写入：`- YYYY-MM-DD — （自动）<一句话> · [巡检](../../reviews/nightly/YYYY-MM-DD.md)`

## 偏好
`profile/preferences.md` 对应小节：
```markdown
- <偏好，一句话> —— YYYY-MM-DD，<来源：对话 / 问卷 xNN / journal>
```
新偏好覆盖旧的时，在后面加「（曾经：<旧说法>，<日期>）」。

## 人设风格
`profile/persona.md` 的「风格记录」：
```markdown
- <说法或习惯，一句话；好的写「这样说」，不要的写「别这样说」> —— YYYY-MM-DD，<来源：对话 / journal>（<对内 / 对外>）
```
只记你的明确反馈（夸了、纠正了、指定了），不自己发明。新的覆盖旧的时加「（曾经：…，日期）」。

## todo
```markdown
- [ ] <事项> · <截止日期，可选> · <来源链接>
```
需要拆解、需要验收标准的，不放 todo，按 `plan` skill 建计划。

## 以后再说
```markdown
- [ ] <事项> · 来源：<链接> · 放入：YYYY-MM-DD · 再看的条件：<什么情况下拿出来>
```

## 计划任务
格式和字段以 [plan skill](../.claude/skills/plan/SKILL.md) 为准：
```markdown
- [ ] T1 <动词开头的任务> · @me · exec:me · proj:<slug> · start:YYYY-MM-DD · due:YYYY-MM-DD · upd:YYYY-MM-DD
  - 验收：<做到什么程度算完成>
  - 说明：<背景、范围；派给 agent 时就是 brief 的主体>
  - 授权：<可选，派给 agent 且配跟进时：你授权跟进 Agent 替你做什么、能派哪些角色的子任务（写 --role <slug>）、什么必须升级>
  - 进展：<最近一次进展>（YYYY-MM-DD）
```
多仓库工作面（如 `example-project`）在任务行加 `repo:<仓库名>`，派发时用它（`--repo` 可覆盖）。
状态：`[ ]` 待办 · `[~]` 进行中 · `[!]` 受阻 · `[x]` 完成 · `[-]` 放弃

## 执行说明
当日计划或计划里、要到项目目录去做的任务，在任务下加一条（早上确认今日事项时由 morning-brief 写）：
````markdown
  - 执行：本设备路径 `<python tools/device.py show 查到的路径>`；启动（可选）`claude -n "[执行] <项目> · T<n> <任务>"`
    开场粘贴：
    ```text
    目标：<做完是什么样>
    背景：<为什么做；相关 PR / issue / 档案>
    验收：<怎么算完成，可检查>
    约束：<不碰什么；推送、合并、发布前先问我>
    授权：<可选，给跟进 Agent 的：可以替我做什么、能派哪些角色（--role <slug>）、什么必须升级。派发时移进运行记录「授权」，不发给执行会话>
    做完：<用三五句话总结改了什么、怎么验证的，回到 assistant 晚上汇报>
    ```
````
- 有确认过的执行方案（规划 Agent 出，`plans/exec/`）或 PRD 时，在任务下加一行 `- 执行方案：[<标题>](../exec/<文件>.md)` / `- PRD：[<标题>](../prd/<slug>/prd.md)`，派发时运行记录的「授权」就从它生成；开场粘贴可以省掉（dispatch.py 用方案的目标、验收、约束拼任务说明）
- 不是每个任务都要写：沟通类、查看类的小事写一句路径或链接就够
- 派发时，这段说明就是派发给 agent 的 brief

## 训练记录
`private/health/training-log.md`，**最新的在最上面**：
```markdown
## YYYY-MM-DD（周X）<A 日 / B 日 / 休息>
| 动作 | 类型 | 重量 | 次 × 组 | 完成情况 |
|---|---|---|---|---|
| 示例动作 A | 主项 | 20kg | 5×5 | 完成 / 第 4 组只做了 3 次 |
| 示例动作 B | 辅项 | 10kg | 8×5 | |

- 感受：<状态、疼痛、睡眠等>
- 下次：<按递进规则的下次重量，或者「不加重，原因 …」>
```
- 组次统一记为 **次 × 组**（`5×5` = 5 次 × 5 组，`8×5` = 8 次 × 5 组）
- 休息日只写标题和一句原因
- 每次记完更新 `private/health/index.md` 的「主项当前重量」

## 饮水
`private/health/water-log.md` 的表格，**每天一行**，最新的在最上面：
```markdown
| YYYY-MM-DD | <N> 杯 × <每杯 ml> | <其他，约 ml> | <合计 ml，有估算就写区间> | <目标区间> | ✅ 达标 / ❌ 差 <ml> |
```
- 有估算的照你的说法写区间（例如「约 200–300」），合计也写区间；达标按合计的上限判断
- 目标改了就改 `private/health/index.md` 的「追踪指标」，并在时间线记一笔

## 训练计划
`private/health/index.md` 的「训练计划」小节直接改写；改动在时间线加一行，写清改了什么、为什么。

## 体检记录
`private/health/index.md` 的「体检记录」表格，追加一行：
```markdown
| YYYY-MM-DD | <指标> | <数值 + 单位> | <参考范围 / 来源 / 备注> |
```
日期不确定写「YYYY-MM?」或「最近一次（日期待补）」；单位是推断的要标出来。

## 财务
`private/finance/index.md` 对应表格，追加一行：
```markdown
| YYYY-MM-DD | <项目> | <金额 + 币种> | <备注> |
```
结论和决定写进 `areas/finance/index.md`；有取舍的财务决定提议建 decision。

## 术语
`memory/glossary.md` 的表格：
```markdown
| <术语 / 别名> | <含义；链接到对应档案> | <来源：对话日期 / 问卷 / README> |
```
含义不确定的写「?」或「（推断）」，确认后去掉。

## 汇报卡片
向你汇报要你回复的事时，一件一张（[report-cards skill](../.claude/skills/report-cards/SKILL.md)，整份样式见 [report-cards.md](report-cards.md)）。整张用引用块包起来，标题 + 五块：
```markdown
> **▍卡片 <N> · <项目> · <事项> · <要拍板 / 待验收 / 待查看 / 待回复>（<编号>）**
>
> **背景**：<一两句：做到哪了、谁做的，带提交号 / PR 号 / 时间>
>
> **遇到的问题**：<为什么要你回：卡在哪、超出了哪条授权>
>
> **选项**
> - **A（推荐）**<做法> —— <理由>
> - **B** <做法> —— <代价>
>
> **我的建议**：A，理由：<一句>
>
> **怎么回复**：<回「A」即可 / 打开 <绝对链接>（已核对 HH:MM），<做完什么>，<粘回哪个会话>>
```
没有选项可给的，「选项」换成「**需要你补充什么**：<缺什么信息>」。A 永远是推荐；链接一律绝对（`file:///D:/…`、`http://127.0.0.1:端口/`），发之前核对能打开。

卡片后面的进展表，一件事一行（有卡片的不重复）：
```markdown
| <项目 slug> | <计划任务号 + 事项；有卡点写卡点> | <🟢 进行中 / 🟡 等你 / 受阻 / 🔴 出问题 / ⏸ 暂停 / ✅ 已完成 / ⚪ 排队> | <一句话带依据> | <下一步：谁做什么，需要时才加这一列> |
```

## 规范变更
`playbooks/README.md` 的变更记录，**倒序**（新的在上）：
```markdown
- YYYY-MM-DD — <改了什么规范：skill / playbook / 模板 / CLAUDE.md，一句话> · [journal](../journal/YYYY/MM/YYYY-MM-DD.md)
```
