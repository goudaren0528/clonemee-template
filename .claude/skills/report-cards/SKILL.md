# 汇报卡片 `v0`

卡片样式：待处理事项一堆文字不好扫、不好回，所以**要你回复的事一件一张卡片，事情进展用表格**，每次汇报长得一样，你扫一眼就知道该回什么、怎么回。交互使用（主会话），对外内容不用。
模板：[templates/report-cards.md](../../../templates/report-cards.md)（整份回复）· [entries.md#汇报卡片](../../../templates/entries.md#汇报卡片)（一张卡片、进展表一行）。

## 1. 什么时候用、用哪种卡片

| 场景 | 卡片类型 |
|---|---|
| 待处理消息「要拍板」「卡住」；早间建议「需要你确认」、周日盘点里要你在几个做法里选一个的 | **要拍板** |
| 待处理消息「完成」：做完了要你体验、看结果再说过不过（体验页、验收报告） | **待验收** |
| 要你打开一份东西看完再回：澄清问卷、PRD 评审页、策划案评审页、调研报告 | **待查看** |
| 只要你补一句信息、确认一件事，没有东西要打开、也没有几个做法可选 | **待回复** |

- 一张卡片只有一种类型，按「你要做的第一个动作」定：要先打开页面的算待查看（哪怕页里有待确认要选）
- **不出卡片**：进展、授权内替你做的决定、已经处理掉的事 → 进展表一行；「交接」消息按 comms 自动处理、做完报一句；对外内容（PR、issue、评论、发给别人的消息）不用这个格式，也不称呼「你」，写使用者的名字或 GitHub 账号

## 2. 取数
```bash
python tools/notify.py list        # 待处理消息：编号、类型、项目：事项、一句话、详情路径
python tools/sweep.py              # 问「还等我什么」「今天要我做什么」时：跟进总表里「等你」「我来处理」的行
```
- 每条消息读它的**详情**（运行记录看「监督」最后几条、报告看结论摘要），背景和选项从这里来，不照抄一句话
- 早间建议确认时读 `plans/daily/<今天>.md` 的「需要你确认」；周日盘点用 `inventory.py` 的结果
- **先确认事情还没过时**：运行记录最新一条可能已经处理完了（例：消息说「待验收」，监督里已经写了验收、上线）。过时的不出卡片，进展表写 ✅，并提醒 `notify.py done <编号>`

## 3. 挑卡片：一次最多 5 张
多于 5 件时按下面的顺序挑，其余只在进展表里一行带过（状态 🟡，进展里写「这次没出卡片，说『看 <编号>』展开」）：
1. 挡着别人干活的：有会话停在提问上、流水线等你点头
2. 逾期、今天到期的
3. 7 天内到期的
4. 同等情况下要拍板 → 待验收 → 待查看 → 待回复
5. 等得最久的

同一件事有几条消息（比如先「完成」后「要拍板」）合成一张卡片，标题带最新的编号。

## 4. 核对链接（必做，发卡片前）
要你「查看后回复」的卡片（问卷、PRD 评审页、策划案评审页、体验页、调研报告、验收报告）**必须带能点开的绝对链接**：
- 本地文件写 `file:///<仓库绝对路径>/plans/prd/<slug>/review.html`（正斜杠，`file:///` 加盘符）；本地服务写 `http://127.0.0.1:<端口>/`
- **不写相对路径**（`../`、`plans/prd/…`），也不写别的设备上的路径；路径以待处理清单的「详情」、运行记录里的绝对路径为准，换设备时按 `python tools/device.py show` 换盘符和目录
- 文件写在 助手仓库主目录（派发会话的产出常在主目录、没提交），不要指到 Orca 工作区里的旧副本

**每个链接发之前都核对一次**：
```bash
test -f "<仓库绝对路径>/plans/prd/<slug>/review.html" && echo ok                          # 文件：存在才算通
curl -s -o /dev/null -w "%{http_code}\n" --max-time 5 http://127.0.0.1:<端口>/    # 服务：200 才算通
```
（PowerShell：`Test-Path <路径>`；`(Invoke-WebRequest -UseBasicParsing -TimeoutSec 5 <地址>).StatusCode`）

**打不开的先修再发**，不发死链：
- 文件不在：找对路径（产出可能写进了项目仓库或工作区），找到了用新路径
- 服务没起：先看运行记录是不是已经验收完、环境按计划关了——是的话这件事已经不是待验收，改成进展表一行；还要你体验的，`python tools/experience.py start <项目>-<需求> --url <地址> --cmd <启动命令> --cwd <目录>` 重新拉起（命令看运行记录或交付看板的「体验」一节），再核对一次
- 一时修不好：卡片里照样出，但「怎么回复」写清「链接现在打不开：<原因>，我在 <做什么>，好了再推给你」
- 核对过的链接后面写「（已核对 HH:MM）」
- 你让帮着打开：`Start-Process msedge <链接>`（Orca 内置浏览器打开本地页面有问题，见改进清单）

## 5. 卡片怎么写
标题 + 五块，整张用引用块（`> `）包起来，块内每块用粗体小标题、块与块之间空一行 `>`：

```markdown
> **▍卡片 <N> · <项目> · <事项> · <类型>（<编号>）**
>
> **背景**：<一两句：做到哪了、谁做的，带提交号 / PR 号 / 时间>
>
> **遇到的问题**：<为什么要你回：卡在哪、超出了哪条授权>
>
> **选项**
> - **A（推荐）**<做法> —— <理由>
> - **B** <做法> —— <代价>
> - **C** <做法> —— <代价>
>
> **我的建议**：A，理由：<一句；为什么要你点头>
>
> **怎么回复**：<回「A」即可 / 打开 <链接>（已核对 HH:MM），<做完什么>，<粘回哪个会话 / 回我一句什么>>
```

- **标题**：`▍卡片 N` 按本次顺序编号；项目写 slug（领域写「life（领域）」这类）；事项短，带计划任务号（T3）；类型是要拍板 / 待验收 / 待查看 / 待回复；有待处理编号（N1022-03）带在括号里，没有就不带
- **背景**：只写事实，一两句；推断标（推断）
- **遇到的问题**：说清为什么这件事非你不可（超出授权、要你本人评审、要花钱、对外……）
- **选项**：2–4 个，**A 永远是推荐**，每个都带理由或代价；没有选项可给的，这一块换成「**需要你补充什么**：<缺什么信息>」
- **我的建议**：重复推荐并给一句理由；拿不准的说拿不准
- **怎么回复**：写具体动作——回一个字母（「回『A』即可，要补话写在后面」）；或者打开链接、做完什么、导出后粘回哪个会话（产品 Agent 会话关了的，粘回主会话，由主会话存档再接回）
- 卡片里不贴令牌、密钥；路径只贴链接，不贴大段内容

## 6. 进展表
卡片后面接一张进展表，放**这次涉及、但不用你回复的事**：卡片放不下的、刚做完的、在跑的、排队的。有卡片的事不在表里重复。

| 项目 | 问题 | 状态 | 进展 | 下一步 |
|---|---|---|---|---|

- **项目**：slug，领域写「life（领域）」；**问题**：这件事是什么（计划任务号 + 事项，有卡点写卡点）；**进展**：一句话带依据（提交、PR、时间）；**下一步**：需要时加这一列，写谁做什么
- **状态词表**（固定）：🟢 进行中 · 🟡 等你 / 受阻 · 🔴 出问题 · ⏸ 暂停 · ✅ 已完成 · ⚪ 排队
- 排序：🔴 → 🟡 → 🟢 → ⚪ → ⏸ → ✅
- 和 [progress-report](../progress-report/SKILL.md) 的关系：这是它六列进展表的简版（见那边第 6 节）；你问「进展怎么样」时用 progress-report 的完整表，里面要你回的事再按本 skill 出卡片

## 7. 整份回复的顺序
1. 一句结论：几件要你回、最急的是哪件
2. 卡片（≤ 5 张）
3. 进展表
4. 一行「一起回」：几张卡片都只要回字母的，提示可以合起来回（「1A 3A」）
5. 「已记：…」

## 8. 你回复之后
- 按回复去做（恢复会话、派发、合并……按 [comms](../../../playbooks/comms.md) 和运行记录里的「恢复」做法），做完 `python tools/notify.py done <编号> --note "<你选了什么>"`
- 你说「这样不好看」「下次 xx」这类对格式的反馈：记进 `profile/persona.md` 的「风格记录」，改规范按派发处理（CLAUDE.md §2）

## 9. 样例（示意，不是真实数据）

> **▍卡片 1 · example-project · 发布前要不要改 PR 的 base · 待拍板（N0000-01）**
>
> **背景**：执行会话当初把需求分支叠在一个已合并的分支上开了 PR，那个分支已经进了 main，叠上去合了也进不了 main。
>
> **遇到的问题**：改 base 等于改验收标准，超出授权，要你定。
>
> **选项**
> - **A（推荐）**PR 的 base 改成 main，单独补规范 —— 风险最小，两种 base 的 diff 一样
> - **B** 保持原 base，以后再开一个 PR 进 main —— 多一轮，没好处
> - **C** 先不开 —— 规范一直不生效
>
> **我的建议**：A，理由：原 base 已合，B 只是绕路。
>
> **怎么回复**：回「A」即可。你回了我在工作区 `claude --resume` 接回执行会话，推送、开 PR 由你决定。

> **▍卡片 2 · example-project · 需求评审页 · 待查看（N0000-02）**
>
> **背景**：产品 Agent 出了 PRD v1.0、4 屏原型和可评论的评审页，工具的检查项已清零。
>
> **遇到的问题**：定稿要你本人看过；页里有 2 条待确认要你选（p01 一个做法取舍，p02 一个边界口径）。
>
> **选项**
> - **A（推荐）**打开评审页逐节看，p01、p02 在页里点选，导出后粘回 —— 定稿前过一遍最稳
> - **B** 不看全文，只回我两个选择，其余默认通过 —— 快，但定稿你没过目
> - **C** 先放着 —— 需求卡在定稿前
>
> **我的建议**：A；页里的推荐都是改动最小的那种，我同意（推断）。
>
> **怎么回复**：打开 `file:///…/plans/prd/example-project/review.html`（发之前核对能打开），评审完点「导出」，粘回主会话。

| 项目 | 问题 | 状态 | 进展 | 下一步 |
|---|---|---|---|---|
| assistant | 汇报卡片 skill | 🟢 进行中 | 执行会话在写 skill、模板和规范 | 做完报「完成」 |
| example-project | 体验验收（N0000-03） | ✅ 已完成 | 你体验后定上线，体验环境已关 | 主会话 `notify.py done N0000-03` |

1、2 都只要回字母，可以合起来回「1A 2A」。

## 禁止
- 发没核对过的链接、相对路径、别的设备上的路径
- 一次超过 5 张卡片；把进展、授权内的决定写成卡片
- 替你选：卡片只给推荐，选项里要有不按推荐的路
- 对外内容（PR、issue、评论、发给别人的消息）用这个格式，或称呼「你」
