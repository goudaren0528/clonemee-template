# 派发任务 `v0`

讨论、确认在助手工作区做，**执行在派发出去的 agent 会话里做**（CLAUDE.md §2）。授权规则：Orca 默认跳过权限确认，等于你已授权；任务说明里的约束保留；每次仍然先出方案、确认后派发。
**所有派发都配一个跟进 Agent，执行方案 / PRD 定稿就是它的授权范围**：跟进 Agent 在范围内按你的做事偏好替你决策，超出才升级。

## 0. 先分清走哪条路
**先按任务类型定「方案」谁出**——没有确认过的方案（执行方案或 PRD），就不派执行：
| 任务类型 | 先出什么方案 | 谁出 | 确认后怎么派 |
|---|---|---|---|
| **开发类**：要改项目代码（功能、修 bug、重构、迁移） | PRD（功能、原型、验收标准） | 产品 Agent（`--role product`，pm-clarify → pm-prd） | 你说「确认派发」→ 开发交付流水线（下表第一行）；小改动可以 `--role dev` 单派 |
| **非开发类**：调研后落地、测试验收、排查后处理、对外沟通准备、事务、生活安排…… | 执行方案（目标、步骤、谁做、验收、风险、授权范围；模板 [exec-plan.md](../../../templates/exec-plan.md)） | 规划 Agent（`--role planner`），方案写在 `plans/exec/<日期>-<slug>.md` | 按方案「谁做」选角色，`tools/dispatch.py` 派，配跟进 Agent |
| **小事**：合 PR、解冲突、一次性查询、照着现成说明做的 | 不用单独出方案：主会话写一段带「授权」行的执行说明，你确认今日事项时一起确认，就算执行方案 | 主会话 | 下面的「轻量派发」 |

- 规划 Agent、产品 Agent 本身直接派（它们就是出方案的）；你在它们的会话里确认后，它们发「交接」，主会话按 [comms.md](../../../playbooks/comms.md) 处理：把方案挂到任务行（`- 执行方案：[…](../exec/<文件>.md)` 或 `- PRD：[…](../prd/<slug>/prd.md)`），你说过「确认派发」的直接派
- 拿不准算哪类：要改代码的就是开发类；其余按非开发类。dispatch.py 发现任务既没引用确认过的执行方案 / PRD、也没有执行说明时会在「检查」里提醒

| 要派的 | 怎么派 |
|---|---|
| **PRD 已定稿的开发需求**（产品 Agent 出的 PRD，你评审确认过） | **开发交付流水线**：`python tools/delivery.py start <项目> <需求slug> --prd <PRD 路径>` 先出方案，你说「确认派发」后加 `--run`。之后由跟进 Agent 全程推进、中间不再问你（授权范围：按依赖派包、本地合包、合回 develop；推送和上线由你来）。只在 Orca 里派；项目要先有 develop 分支 |
| 其他计划任务（执行方案确认过的非开发类、单个开发任务、排查、review…） | 本 skill 下面的步骤，`tools/dispatch.py` |
| **项目上的小事**：合 PR、解冲突、补一个提交、关 issue | 也派发，用下面的「轻量派发」；主会话不自己动手（CLAUDE.md §2） |
| **助手自身的规范修改**（skill、工具、模板、playbook、CLAUDE.md） | 也按本 skill 派发（`--role dev` 或改进会话）：主会话讨论、出方案，你确认后派；主会话不当场改（挡住当前工作的小 bug 除外） |

### 轻量派发（合 PR、解冲突这类小事）
你说「帮我合一下 / 处理一下 / 把冲突解了」= 先出派发方案，**主会话不在项目仓库做写操作**（主会话这么做会被 PreToolUse hook `tools/guard_hook.py` 拦下）：
1. 在今天的当日计划末尾加一个任务行（`proj:` + `repo:` + `exec:claude`），下面只写一段开场粘贴：
   ```text
   目标：合并 <owner/repo>#<PR>（<base> ← <head>）/ 解掉 #<PR> 和 <base> 的冲突
   背景：<为什么现在做；你 HH:MM 确认要合>
   验收：PR 已 merged（或冲突已解、CI 通过）；合并方式按仓库规范
   约束：只处理这一个 PR；冲突只在 PR 的 head 分支上解，解完可以推 head 分支（你已确认）；不动其他分支、不删分支、不关 PR；拿不准停下来问
   做完：一句话报结果（PR 链接、合并提交或解冲突的提交）
   ```
   **合开发分支进 main（或别的长分支）时，说明里写明合并方式：默认 `git merge --squash <分支>`，不用 `git merge`。** 长分支的整段历史会连同里面的验收证据（大 json、截图、gif、日志）一起进 main 的历史，文件树里删了也还在——这样会把几十上百 MB 的证据推上远端。squash 之后工作区里冒出来的证据目录改动一律丢掉（`git restore --staged --worktree -- <证据路径>`），合并结果只留代码和文档；证据留在本机证据目录（`.gitignore` 已排除）。
2. `python tools/dispatch.py --task T<n> --existing`（只读查询 + gh 操作，用仓库现有目录；要改代码解冲突的用 `--new`）出方案，你确认后加 `--run`
3. 你在对话里明确说「主会话直接做」时才例外：命令末尾加注释 `# assistant:direct`，journal 记一笔

## 推进位：同时最多 6 件（默认值，按机器能力调）
起因：同时开太多 agent 会话和工作区会拖垮 Orca，严重时所有会话一起断掉，所以给并发设上限。
- **按设备算**：推进位只看**本机**实际开着的派发会话——`sweep.py` 在本机能看到的那些（多台设备时表里有「设备」一列，标明本机 / 别的设备）；别的设备上跑的占那台设备的位，不在这里计数（`runs/status/<别的设备指纹>.md` 只作参考，标明「在别的设备上」）。今日计划的「推进位与排队」分设备写（表头加「设备」列或分开两张表）
- **一件** = 一个派出去的计划任务：执行会话、跟进 Agent、它派生的子任务、流水线的工作包都算在这一件里。只要有派出去的会话开着，就占一个推进位
- **不占位**：主会话；早间建议、夜间巡检这类无头例行；`@me` 你自己做的；**只在等你的**（等评审、等回复、等验收）——跟进 Agent 把现状写进运行记录「监督」、发完要拍板 / 完成消息后，关掉执行会话和自己（工作区留着），让出位置；你回了，这件排到队首恢复
- **每件同时开着的会话 ≤ 4 个**（跟进 + 3 条线；流水线本来就 ≤ 3 条线）；做完的会话当场关（`follow.py --close`），不留空终端
- **派发前先数**（只数本机）：`python tools/dispatch.py` 出方案时先报「推进位：本机 x/6」（只数本机有会话开着的派发，别的设备上的不计），`python tools/sweep.py` 表里也有本机 x/6 和每件事的设备。本机满 6 件，新事项不派，写进今日计划「推进位与排队」的排队表，告诉你排第几
- **推进位与排队：三栏**（暂停和等外部的任务不占推进位，不单独设一栏的话会落在台账外面没人接）。今日计划里的一节，三张表：
  - **推进中**（≤ 6 行）：本机开着的派发；
  - **排队**（按顺序，写「派发已确认：是 / 否」）：要派、或确认了但没位置的；
  - **暂停与等外部**：只在等你、等别的项目、等外部条件的——**必须写「等谁 / 等什么」和「回来看」（复查日期，YYYY-MM-DD）**，写清等谁做什么、哪天回来看。

  **每个未结任务（计划任务、todo 里的都算）必须落在三栏之一**，哪栏都没有就是漏网；只在等你的、@me 的不占推进位，但要进暂停栏。排序按 截止日期 → 快做完的 → 业务价值，同一项目的两条线尽量错开。早间建议生成时按三栏写、你确认时扫一遍暂停栏。

  **到复查日期（当天或过期）自动进待处理并出卡片**：看条件满足了没有——满足了进推进中或排队，没满足补新的复查日期；暂停项缺复查日期的当场补上。`python tools/board.py` 扫这三类问题（不在三栏 / 缺复查日期 / 到期或过期，过期在前），`sweep.py` 末尾和会话开场卡片也各报一行；每天中午、晚上各刷一次台账。
- **空出位置**：一件完成或转成等你时，主会话报一句「X 让出位置，下一个是 Y」；Y 排队时你已确认派发的，直接派、报一句，没确认的先出派发方案
- **你说插队**（「这个先做」）：照办；满 6 件时先问挤下哪一件，挤下的由跟进 Agent 记好现状、关会话，转成排队
- 崩溃或重启后恢复：只恢复推进中那几件（跟进 Agent 读运行记录接着跟、执行会话用 `claude --resume` / `codex resume` 接回），排队的不动

## 1. 前置
- 今天的 `plans/daily/<日期>.md` 已确认（`status: active`）。还是草案的，先按 `morning-brief` skill · B 确认
- 推进位还有空（上面「推进位」）；满了就进排队，不派
- 要派的任务有 `proj:`，最好在确认今日事项时已经写好「执行说明」（[entries.md#执行说明](../../../templates/entries.md#执行说明)）；没有的话，工具会按任务字段拼一份
- 多仓库工作面（比如 `example-project`）在任务行写 `repo:<仓库名>`，或派发时加 `--repo`

## 2. 出方案（不执行）
```bash
python tools/env.py                                   # 运行环境：在不在 Orca 里、派发方式、可用 agent
python tools/dispatch.py                              # 今天 exec: 是 agent 的任务
python tools/dispatch.py --task T2 --agent codex      # 指定任务和执行器
python tools/dispatch.py --task T2 --role investigate # 按角色派发（agents/investigate.md），注入角色设定，执行器和工作区按角色默认
```
工具会出一张**派发方案表**，原样发给你（任务多、项目多时一眼看清派到哪）：

| # | 任务 | 项目 · 仓库 | 本设备主目录 | 在哪做（新工作区的预计路径 / 现有目录 / 新终端窗口） | 分支 | 谁做 | 带过去的文件 | 检查 |
|---|---|---|---|---|---|---|---|---|

- **检查**：✅ / ⚠（比如主目录有未提交改动）/ ❌（本设备没克隆、没有这个执行器、没有指定的分支）。❌ 的任务不会派，其余照派
- **本设备没克隆**：方案里写了建议路径。你说「克隆 xx」后跑 `python tools/clone.py <owner/repo> --run [--path …]`（克隆 + 登记进 Orca 和本设备路径表），再重新出方案；「确认派发」不顺带克隆
- **带过去的文件**：任务说明里引用到的 assistant 文件（PRD、原型、文档；`private/` 永远不带）。派发时复制进工作区的 `.assistant/handoff/<计划>-<任务>/`（写进 `.git/info/exclude`，不改项目的 `.gitignore`、不会被提交），README 注明来源提交；原件留在 assistant，要改回 assistant 改。任务就在 assistant 本身时不复制。`python tools/handoff.py <计划> <任务>` 可以单独看会带哪些

问清楚：
- 派哪个角色（[agents/](../../../agents/INDEX.md)：产品 / 规划 / 开发 / 验收 / 跟进 / 调研 / 排查；角色状态看各自 `agents/<slug>.md` 的 status（draft 的先看说明），拿不准时先看角色说明 `agents/<slug>.md`；执行方案确认过的按它的「谁做」），用哪个执行器（谁说了算：`--agent` > 角色默认 > 任务 `exec:` > 兜底；兜底时改代码的用 OpenCode、其他用 Claude Code，方案里会标「兜底」）
- Orca 里新建工作区还是用现有目录：按角色默认——开发、产品新建工作区，排查、调研、单独验收用现有目录；没有角色时只读排查、文档整理用现有目录，其余新建。方案里写了选哪种和理由，你要改就加 `--new` / `--existing`
- 任务说明的约束对不对：默认是**不 push、不合并、不发布、不删除；需要时先停下来问**
- **任务涉及界面 / 网页验证时**，任务说明里写明：用 Orca 内置浏览器（`orca tab create --url` / `orca goto` / `orca snapshot` / `orca screenshot`），截图存 `runs/shots/<日期>-<任务>/` 或项目 `docs/delivery/<需求>/…/shots/`（证据不进 git），打不开 / 点不动时换 Edge 无头，**报告里写清用了哪条路和原因**；不要用 computer use 操作内置浏览器，桌面 GUI 才用 `orca computer`（[playbooks/orca.md](../../../playbooks/orca.md)）
- 跟进 Agent 的**授权 = 确认过的执行方案或 PRD**：dispatch.py 按这个顺序生成运行记录「授权」一节——任务引用的执行方案（`plans/exec/`，status active）> 引用的 PRD（status active，定稿）> 任务自己的执行说明（当日计划已确认）；生成范围、验收、可以替你定、可以派的角色、必须升级几行，范围内按 `profile/preferences.md` 决策。你另外写的边界放任务行下的「- 授权：」子项或开场粘贴里以「授权」开头的一行（[entries.md#执行说明](../../../templates/entries.md#执行说明)），原样记成「你写明」、优先于生成的默认值。都不发给执行会话；方案「说明」里显示授权来源。执行方案的「可以派的角色」或你写明里点了角色（`--role <slug>`），跟进 Agent 才能派生子任务（`follow.py --spawn`，task-follow 第 7 节）；都没有 = 默认边界、不能派生
- 多仓库工作面：任务行的 `repo:` 决定派到哪个仓库（`--repo` 可覆盖），方案表「项目 · 仓库」一栏核对一下

## 3. 派发（你说「确认派发」之后）
```bash
python tools/dispatch.py --task T2 --agent codex --run
```
- **在 Orca 里**（或本机 Orca 正在运行）：新建 Orca 工作区 + 启动 agent + 发任务说明，然后给工作区和终端标签起名「[执行] 项目 · T2 …」，并在工作区备注里写 `assistant <计划>#T2`
- **不在 Orca 里**：在项目目录开新终端窗口，启动带名字的 agent，让它先读运行记录里的任务说明
- **派发标识**：每次派发都记下是哪个主会话派的（会话 ID 前 8 位 · 日期 · 终端标题）：派发记录的 `dispatched_by`、Orca 工作区备注「派自 …」、任务说明里的「派发标识」一行；跟进总表的「派发」一格显示「派自 xxxx」
- 派完出一张**派发结果表**（任务、项目 · 仓库、实际工作目录、分支、会话、运行记录），也原样发给你
- 工具会写运行记录 `runs/<日期>-<计划>-<任务>.md`（模板 [run.md](../../../templates/run.md)，「派发」一节有同样的表和带过去的文件清单），并把任务改为 `[~]`、回填 `run:`、加一条带工作目录的进展
- **回报给谁**：派发的这个主会话。运行记录写 `report_to`（本会话的 Orca 终端），任务说明末尾带上 `tools/notify.py send` 回报命令；派出去的会话只在完成、要拍板（产品 Agent：交接）时发，先进待处理清单 `runs/pending.md`、再推一行进来（[comms.md](../../../playbooks/comms.md)）
- **所有派发默认同时派一个跟进 Agent**（[agents/pm.md](../../../agents/pm.md)，固定 Claude Code，在助手仓库里启动，按 [task-follow](../task-follow/SKILL.md) 做）：定期看执行会话、在授权（执行方案 / PRD）内按你的做事偏好替你决定、做完验收并汇报。方案里会一起列出来；你说不要跟进时加 `--no-follow`（`--follow` 保留兼容，不用再加）。有跟进时执行会话不回报主会话，产品、规划 Agent 例外：定稿后自己发「交接」

## 4. 监督
- **跟进总表 / 回收**：`python tools/sweep.py` 出一张表，每个「项目：事项」一行：当前进度、派发了没有、执行会话（名字 · 状态 · 最后输出）、跟进会话、现在等谁、下一步；来源是进行中的计划任务、没结束的派发、Orca 里没登记的会话（你自己开的、别的主会话、团队 worker 归成一行）。给你汇报时**原样用这张表**；Orca 里没登记的会话（你自己开的、别的工具派的）用 `sweep.py adopt` 收编：补一份派发记录（kind: adopted）、收回最后的总结、待处理清单补一条「完成」；团队 worker 和主会话不收。做完没回报的用 `sweep.py reclaim <运行记录>` 把最后的总结收进「验收」、在待处理清单补一条「完成」（不改任务状态，等你验收；`--close` 顺手关终端）。你问「派出去的都怎样了」、或者开场发现有派发很久没动静时跑
- 日常监督由跟进 Agent 做：它把进展、替你做的决定、验收写进运行记录的「监督」「决策记录」「验收」；主会话只看运行记录和它的汇报
- 看某个任务的现状：`python tools/follow.py runs/<x>.md`
- 收到一行 `【assistant 消息 · …】`、或者启动时「待处理 N 条」：按 [comms.md](../../../playbooks/comms.md) 处理（交接自动合并 PRD），处理完 `python tools/notify.py done <编号>`
- `python tools/dispatch.py --status`：列出运行记录；在 Orca 里还会显示工作区有没有活动、在哪个分支
- Orca 里需要看细节时：`orca terminal read --terminal <handle> --json`、`orca worktree ps --json`（只读）
- 没配跟进 Agent 时（`--no-follow`），主会话每次检查在运行记录的「监督」一节加一行；晚上的 `daily-update` 对照运行记录问你结果
- 完成后：运行记录填「验收」，`status` 改为 done / failed；计划里的任务改状态、写进展

## 5. 收尾
journal 记一条（派了什么、给谁、在哪）；更新会话记忆；`python tools/build_index.py`；提交并推送。

## 禁止
