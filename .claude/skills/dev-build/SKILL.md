# 按包实现与自测 `v0`

开发 Agent 用。参考了团队 prd-to-delivery 的做法：PRD 唯一基准、原子步骤、一手证据、不扩范围。

## 开工（每次进会话都先做）
1. 读：`prd.md`、`impl-plan.md`（技术方案、接口约定、本包那一行）、`cases.md`（验收会怎么测，可以当目标）
2. 读本包的进度文件 `packages/P<n>.md`：
   - 没有：按模板 `{assistant}/templates/package.md` 建，把本包拆成**原子步骤**（每步改哪里、怎么验证），一步一个勾
   - 有：从第一个没打勾的步骤接着做，先看「交接」
3. 确认当前分支是派发说明里的分支

## 实现
- 一次只做一步；做完一步：跑这一步的验证 → 提交（中文提交信息）→ 在进度文件里打勾、写提交号
- 匹配项目现有写法：动手前看 2–3 个同类文件和 lint / 格式化 / 类型检查配置
- 只改本包「文件归属」里的文件；确实要动别处（比如 P0 的接口不够用）→ 在终端里说清楚，等跟进 Agent 回复
- PRD 没覆盖、拿不准的 → 写进进度文件「交接」，在终端里问；不猜、不扩范围
- 涉及数据迁移：只在本地或测试环境跑，验证回滚、重复执行、旧数据兼容，结果写进自测

## 自测（交审查前必须做完，都要一手证据）
| 项 | 怎么做 |
|---|---|
| 单元测试 | 给本包的逻辑补测试；跑项目的测试命令，记录命令和结果（通过数、退出码） |
| 构建 / 类型检查 / lint | 项目有就跑到通过 |
| 冒烟 | 启动服务，走一遍本包涉及的主流程（页面能打开、接口能通） |
| 性能 / 安全自查 | **只看本包的变更路径**：N+1 查询、循环里的 IO、大数据量；鉴权、注入、敏感信息泄露、输入校验。有问题就改，没有就写「已查：无」 |

**界面冒烟用 Orca 内置浏览器**（在 Orca 里时）：`orca tab create --url <本地地址>` 或 `orca goto --url <地址>` → `orca snapshot --json` → 点 / 填 → **再 snapshot**（ref 导航后就失效）→ 关键状态 `orca screenshot --format png --json` 存 `packages/shots/P<n>/`，**证据不进 git**。打不开、点不动、`about:blank`、导航超时时先按 [accept-test](../accept-test/SKILL.md)「打不开 / 点不动的时候」兜底，最后换 Edge 无头，**把用了哪条路、为什么写进进度文件的「自测」**；没真看到页面就不写「冒烟通过」。不要用 computer use 操作内置浏览器，桌面 GUI 才用 `orca computer`（[playbooks/orca.md](../../../playbooks/orca.md)）。

测试失败如实写，附输出；不删测试、不硬编码结果、不跳过钩子。

## 交审查
1. 进度文件写好「自测」和「交接」（做到哪、注意什么），提交
2. 在终端里说「P<n> 可以审查了」，附三五句话：做了什么、怎么验证的、还剩什么
3. 等跟进 Agent 的安排（可能会让你在这个会话里继续修复）

## 禁止
- 推送、合并、切换分支；改 develop / main
- 改 cases.md、审查报告、测试报告；给自己下审查结论
- 没跑过就写「通过」
