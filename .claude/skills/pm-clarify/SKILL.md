# 需求澄清 `v3`

产品 Agent 用。目标：**用最少的轮次，把需求问清楚到可以写 PRD**。默认用可视化选择批量回答（模板里的默认做法，按 `profile/preferences.md` 调整），所以问题做成 HTML 问卷，不在对话里连环问。

## 文件布局（每个需求一个目录）
```
plans/prd/<需求 slug>/            # 在助手仓库里；在别的项目里，用项目约定的文档目录
  clarify-01.yaml / .html       # 第 1 轮问卷（题目清单 + 生成的页面）
  answers-01.md                 # 第 1 轮你的回答（你导出后粘贴的原文）
  requirements.md               # 澄清后的需求要点（每轮更新）
```

## 步骤

### 1. 理解
- 读你的原话；同一个需求目录下有调研 Agent 的现状报告（`research.md`）就先读它；需要时再读项目里的代码、文档、issue（只读），搞清楚现状
- 列出已知的：目标、用户、场景、范围、约束、验收标准、优先级、风险。每一条标「你说的」还是「我推断的」

### 2. 找缺口，出题
按下面几个维度找不清楚、有歧义、互相矛盾的地方，只问**会影响方案**的问题：

| 维度 | 典型问题 |
|---|---|
| 目标 | 为什么做、做成什么样算成功（尽量可衡量） |
| 用户与场景 | 谁用、什么时候用、现在怎么解决的 |
| 范围 | 第一版必须有什么、明确不做什么 |
| 约束 | 时间、技术、依赖、权限、合规 |
| 验收 | 怎么验收、谁验收 |
| 优先级与取舍 | 冲突时先保哪个 |

出题规则：
- 一轮 **8–15 题**，能用选择题就用选择题（给 2–5 个有代表性的选项，必要时 `other: true`），开放题放最后
- 每题配 `hint`，说明为什么问、会影响什么
- 选项写成具体方案，不写空泛的「看情况」
- 已经能从记录里确定的，不要再问

**让你答得快**（v3）：
- **每题给推荐答案和理由**：`recommend:` 写推荐的选项（多选写数组，文本题写建议的说法），`why:` 一句话理由。选项上会标「推荐」，你可以点页首「其余按推荐填」把没答的题一次填上，导出时标「（按推荐）」。没把握推荐的题就不写 recommend，别硬给；不要再在选项文字里写「（建议）」
- **比较方案的题加选项预览**：「布局 A 还是 B」「流程怎么走」这类，给选项写 `previews`，你点选项旁的「看图」展开、「并排看全部预览」对比。三种写法：`mermaid:`（流程、时序、状态）、`html:`（一小段界面，自动带视觉规范的变量）、`img:`（图片路径，相对 YAML，生成时内嵌）。预览要小而准，只画区别所在
- **按优先级分组**：会影响方案的题放进 `priority: true` 的分区（排在最前、标「必答」）；锦上添花的放后面。单独某题必答写 `required: true`。页面自动估每组用时，你可以「只看必答」先答要紧的

### 3. 生成问卷
按格式写 `clarify-NN.yaml`（格式见 `tools/qform.py` 开头的说明；完整示例 `tools/samples/prd-demo/clarify.yaml`，用上了推荐、预览、必答），然后：
```bash
python tools/qform.py plans/prd/<slug>/clarify-01.yaml
```
工具会检查 recommend 是不是选项之一、预览对不对得上选项、图片在不在，不对就直接报错退出，改了再生成。

回复你：**一句话说明这轮想搞清楚什么**、问卷的**绝对地址**（直接用工具输出的 `file:///…` 链接，不写相对路径）、大概几分钟（必答几分钟，页首也会显示）。提醒你：可以先「只看必答」，同意推荐的直接点「其余按推荐填」；问卷支持分批回答、暂不回答、补充说明，答完点「导出回答」复制回来。

### 4. 整理回答
你粘贴回答后：
- 原文存进 `answers-NN.md`（不改动）
- 更新 `requirements.md`：每条需求写清结论和出处（题号）；「按推荐」的照样算你的结论，但出处标「按推荐」，写 PRD 时这些题的取舍放进 `> [!决策]` 让你评审时再看一眼；「暂不回答」的记为待定
- 判断还缺什么：缺的会影响方案就出下一轮（`clarify-02`），不影响的记为假设

### 5. 结束条件
目标、用户、范围、验收都清楚了，剩下的待定项不影响第一版方案 → 告诉你「可以写 PRD 了」，转 `pm-prd` skill。

问卷页面的样式按视觉规范（`tools/ui-tokens.css`，见 `pm-prd` skill「视觉规范」），工具会自动内嵌，不用手改。

## 禁止
- 替你回答问题，或者把推断写成结论（推荐答案只是推荐，你没选就不算）
- 一轮问超过 15 题；问和方案无关的问题
- 修改业务代码
- 回复里给相对路径（你要能直接复制打开）
