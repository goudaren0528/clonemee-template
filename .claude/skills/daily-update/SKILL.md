# 每日进展整理 `v1`

你每天会口述当天进展，形式不限（一段话、列表、语音转文字、零散几句）。你负责整理并更新各类信息。

## 0. 前置
- 过了零点说「今天」，默认指前一天，回复里说明这个假设
- 说的是前几天的事：写进对应日期的 journal，标题后加 `(补记 YYYY-MM-DD)`
- 口吻：journal 省略主语，只写事；推断标「（推断）」

## 1. 拆解 + 检索
1. 把口述拆成条目。每条判断：
   - **归属**：哪个工作面（`projects/<slug>`）、领域（`areas/<slug>`、健康、财务），或某个计划（`plans/`）；都不属于就归「其他」
   - **类型**：进展 / 卡点 / 待办 / 决策 / 偏好 / 状态（心情、精力、身体）/ 人 / 会议 / 日期 / 训练 / 支出 / 学习
2. 对提到的项目、人、术语先检索：`python tools/recall.py <关键词>`（L1），需要时再读原文。不认识的简称先查 `memory/glossary.md`
3. 看进行中的计划任务：`python tools/plan.py`，把口述和任务对上；同时刷一次今日计划的「推进位与排队」三栏并跑 `python tools/board.py`（每天中午、晚上各一次，见 CLAUDE.md §4），有要处理的跟你说一句；有 `plans/daily/<当天>.md` 的话逐项打勾，没完成的问一句要不要顺延到明天
4. 对不上已有工作面的工作内容，先记进 journal，在回复里问要不要建档。只有你能确认 tracked

## 2. 对照客观数据（涉及代码工作时）
先看当天有没有夜间巡检的结果：`reviews/nightly/<日期>.md`，以及 journal 里的「夜间巡检（自动）」。有就直接用它的客观部分，不重复采集；你的整理补上你口述的主观上下文（为什么做、卡在哪、不在代码里的工作）。没有再跑：
```bash
python tools/collect.py --since <当天日期>
```
- 以口述为准，提交和 PR 作为佐证，引用 PR 链接或 issue 号
- 你让你「读 diff / PR 来更新」时：用 `gh api repos/<repo>/commits?since=…`，以及 `gh api repos/<repo>/commits/<sha>` 看改了哪些文件、加减多少行，按功能概括，不搬提交列表
- 有提交、但口述没提到的工作面，在「要你确认」里列一行

## 3. 写 journal
`journal/YYYY/MM/YYYY-MM-DD.md`：文件不存在就按 `templates/journal.md` 新建，存在就追加。
- 一个主题一条 `## HH:MM 标题`，带 `#project/<slug>` / `#area/<slug>` 等标签
- 具体写做了什么、结果如何、卡在哪
- 当天最后一次汇报（晚间总结、说「收工」）时，追加一条 `## HH:MM 今日小结`：一两句，今天真正推动了什么、卡在哪

## 4. 落地到各文件
每类写入之前，先按 [templates/INDEX.md](../../../templates/INDEX.md) 找到对应模板（多数是 [entries.md](../../../templates/entries.md) 里的条目模板），按模板写。

| 类型 | 更新 |
|---|---|
| 项目进展 | 项目档案的「当前状态」（标更新日期）「在做」，时间线加一行（回链 journal） |
| 计划里的任务有进展 | 改计划文件里任务的状态标记（`[~]` 进行中、`[!]` 受阻、`[x]` 完成），在计划的「进展日志」加一行 |
| 新冒出来的工作任务 | 属于已有计划的，加进计划；需要拆解、需要验收标准的新事项，按 `plan` skill 起草计划；零散小事进 `todo.md` |
| 卡点、待确认 | 项目档案的「待确认」或「待办」 |
| 状态变化 | `profile/now.md` 对应的块，标更新日期；心情和精力可以推断，要标明 |
| 偏好、纠正 | `profile/preferences.md`；影响助手行为的同步改 CLAUDE.md |
| 人 | 有协作信息（偏好、关注点、约定）的建或更新 `people/<name>.md`；只提了一句的留在 journal，在术语表记一行 |
| 会议 | 有结论或行动项的建 `meetings/YYYY-MM-DD-<topic>.md`；否则写进 journal 就够 |
| 重要日期、出行、家庭事务 | `areas/life` |
| 训练 | `private/health/training-log.md`，并更新健康档案的「主项当前重量」 |
| 饮水 | `private/health/water-log.md`，每天一行（entries.md#饮水）；没报就在回复末尾问一句 |
| 支出、订阅 | `private/finance`（金额），`areas/finance`（结论） |
| 学习 | `areas/learning` 的进度表；顺手推荐一两个资料（标推断） |
| 决策 | 提议建 decision 文件，你同意再建 |
| 新术语、别名 | `memory/glossary.md` |

新建或改动文档时写好 frontmatter 的 `summary` / `status`；索引由 `python tools/build_index.py` 自动生成，收尾时跑一次。

## 5. 会话记忆
更新本次会话的 `memory/sessions/<日期>-<会话ID前8位>.md`：要点只写指针（链到 journal 条目），未结和我的承诺写清楚。改完跑 `python tools/build_index.py`（包含记忆索引）。细则见 `playbooks/memory.md`。

## 6. 追问
记录缺关键信息时追问，**最多 3 个**，按重要性排序。不影响记录的细节不问。

## 7. 回复（固定格式，先结论）
进展表每件事一行，**第一列是项目**（slug；领域写「health（领域）」这类，都不属于写「其他」）：当日计划里的事项逐项列出，口述里计划外的事也列上。
```
今天：<一句话，今天主要推动了什么>

| 项目 | 事项 | 今天的进展 | 状态 |
|---|---|---|---|
| <slug> | <今日事项或口述里的一件事> | <一句话，带依据> | ✅ 完成 / 🟢 推进中 / 🟡 卡住 / ⏭ 顺延 |

更新了：
- <文件>：<改了什么>（只列有改动的）

要你确认：（没有就省略）
1. …

建议（推断）：（没有就省略）
- …

已记：<文件列表>；已提交 <hash>（推送状态）
```

## 8. 提交
整理完就提交 git，message 用中文，例如 `docs: 2027-03-09 日进展`。推送按 CLAUDE.md §5 处理。

## 周日晚上
周日晚上的汇报整理完后，问一句要不要接着做周回顾（`playbooks/weekly-review.md`），其中包括计划复盘和记忆巩固。
