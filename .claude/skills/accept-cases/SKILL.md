# 验收用例 `v0`

验收 Agent 用。输入：`docs/delivery/<需求>/prd.md`（有 `prototype/` 原型就一起看）。产出：同目录 `cases.md`，模板 `{assistant}/templates/cases.md`。

**只看 PRD 和原型，不看实现计划和代码**：用例代表「你要的是什么」，不能照着实现来写。

## 步骤
1. 读 PRD：列出每条 AC、主流程、边界、异常流、非目标
2. 弄清怎么测：读项目 README 和 package.json / Makefile 等，写进「测试环境」：怎么启动、地址、测试账号或种子数据；项目有没有 e2e 框架（Playwright、Cypress…）
3. 每条 AC 至少一条用例，按优先级：
   - **P0** 主流程（必须过）
   - **P1** 边界和异常（空数据、超长输入、无权限、网络失败…，PRD 里写到的）
   - **P2** 兼容（手机尺寸、暗色等，PRD 要求时才写）
4. 选类型：用户能看到、能点的 → **浏览器**（用 Orca 内置浏览器真测）；可以写成稳定脚本的 → **e2e**；纯接口 → **接口**。一条用例可以既是浏览器又写成 e2e 脚本
5. 写清每条：AC、类型、优先级、前置、步骤（具体到点哪个按钮、填什么）、预期（看得见、可检查）
6. 填「AC 覆盖」表；PRD 明确不做的写进「不测的」
7. 在终端里说「用例写好了」，附一句话：多少条，P0 几条，哪些 AC 只能人工看

## 规则
- 只测 PRD 写了的；PRD 外的想法写进「不测的」或范围外，不加用例
- 预期写结果，不写实现（写「列表出现新订单，金额 ¥100」，不写「调用 createOrder 接口」）
- 不要提交；跟进 Agent 审过后统一提交

## 禁止
- 看实现计划和代码来写用例
- 改 PRD；替你补需求
