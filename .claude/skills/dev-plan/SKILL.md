# 实现计划 `v0`

开发 Agent 用。输入：`docs/delivery/<需求>/prd.md`（唯一基准，验收标准编号 AC-n）。产出：同目录 `impl-plan.md`，模板 `{assistant}/templates/impl-plan.md`（派发说明里给了实际路径）。**这一步不写业务代码、不提交。**

## 步骤
1. **读 PRD**：提取目标、非目标、每条 AC、边界和异常流。PRD 有缺失或矛盾、会影响方案的，在终端里提出来等跟进 Agent 回复，不带着猜测往下写
2. **读代码**：项目的 CLAUDE.md / AGENTS.md / README、要改的模块、2–3 个同类实现、测试和构建方式。方案要和现有写法一致，引用具体文件路径
3. **判断数据迁移**：表结构、历史数据、默认值回填、索引变更。涉及就单独成一个包，名字带「迁移」，写清回滚、幂等、旧数据兼容，并在「风险与待定」写「需你确认」
4. **拆工作包**（最关键）：
   - 每包 ≤ 1–2 天，能独立开发、独立审查、独立验证
   - **文件归属**：每包写清改哪些文件或目录，包之间**不能重叠**；重叠就合并成一个包或调整边界
   - **依赖**：只写真正的先后关系；共享的接口、类型、数据结构、配置先做成 **P0 契约包**，其他包依赖 P0 后就可以并行
   - 能并行的尽量并行，但不为并行硬拆（拆出来要互相等的，不如合成一个）
   - 只有一个包也可以：那就直接在需求分支上开发
5. **接口约定**：写出包之间共享的函数签名、类型、接口路径和字段，P0 照这个落地，其他包照这个引用
6. **自测计划**：每包的单元测试覆盖什么、冒烟怎么跑（启动命令和主流程）、性能和安全看哪些变更路径
7. **AC 覆盖**：PRD 每条 AC 都要落到某个包；PRD 外的想法写进「风险与待定」，不进工作包
8. 写完在终端里说「实现计划写好了」，附一句话：几个包、哪些可以并行、有没有迁移

## 工作包表的格式
`tools/delivery.py approve` 会读这张表，列名和格式不能改：包号 `P0`、`P1`…；依赖写包号，逗号分隔，没有写 `—`。

## 审核之后
跟进 Agent 会回复「通过」或要你改哪里。改完再说一次「改好了」。通过后由跟进 Agent 提交，你的这个会话就结束了。

## 禁止
- 写业务代码、提交、切换分支
- 把 PRD 范围外的功能、重构写进工作包
- 文件归属重叠的包标成可以并行
