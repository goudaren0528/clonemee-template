# 早间建议 `v1.3`

分两种模式。

## A. 生成（由派发的独立 session 执行：定时任务，或交互时补跑；无人值守）
没有人会回答问题。只写下面列出的文件，拿不准的写进「需要你确认」。

### 1. 取数
```bash
python tools/plan.py --report        # 项目和计划任务的进展
python tools/plan.py                  # 未完成任务：逾期、进行中、7 天内到期
python tools/inventory.py             # 所有来源的未结事项（已去重）
python tools/gh_tasks.py status       # 用 GitHub 管任务的项目：milestone 进度、未关的 issue
python tools/sweep.py --snapshot      # 跟进总表：每件事一行（项目、事项、进度、派发了没有、执行会话、跟进会话、现在等谁）；写本设备快照，并列出别的设备的快照
python tools/board.py --json          # 台账扫描：不在三栏的未结任务、暂停没写复查日期的、复查日期到了或过期的（先按它补台账）
python tools/schedule.py --json       # 固定日程（areas/work/index.md 的「固定日程」表）：今天、明天、今天该提前提的
```
再读：
- `plans/goals.md`，以及本周的 `plans/weekly/YYYY-Www.md`（如果有）
- 最近一份 `reviews/nightly/*.md`（昨晚的巡检）
- `memory/INDEX.md`，以及最近 2 份会话记忆的「未结」和「我的承诺」
- `profile/now.md`；`areas/life/index.md` 里 7 天内的重要日期
- `areas/work/index.md` 的「固定日程」表（数据源，`tools/schedule.py` 负责解析；只在要改数据或核对写法时看原文）
- `private/` 只读 `private/health/index.md` 的「训练计划」，用来判断今天是不是训练日；其余不读，也不写

### 2. 判断
- **表格第一列是「项目」**：写项目 slug（和任务行的 `proj:` 一致），领域写「life（领域）」这类，工具推不出来的「?」写之前查清补上；任务行标题也用「项目：事项」
- **推进位与排队：三栏**：按 dispatch skill「推进位」排成三张表——**推进中**（本机有派出去的会话开着的，别的设备上的另算、注明设备，≤ 6 件）、**排队**（截止日期 → 快做完的 → 业务价值，同一项目错开；今日建议里要新派的事项也排进来，超出的写「排队第 N」）、**暂停与等外部**（只在等你、等别的项目、等外部条件的，**必须写等谁 / 等什么和回来看的日期**）。**每个未结任务都要落在其中一栏**；`board.py` 报的漏网项（不在三栏）补进对应栏，暂停缺日期或到期的写进「需要你确认」
- **跟进总表**：今日建议里加一节「在跟的事」，**原样用 sweep 的表格**（列：项目｜事项｜当前进度｜派发｜执行会话｜跟进会话｜现在｜下一步，固定格式），不要改写成文字；sweep 里「做完没回报」「等你」「会话没了」「停着」的，写进今日建议的「需要你确认」；别的设备快照里要处理的，注明在哪台设备上（会话只能在那台设备上处理）
- **本设备缺克隆**（`python tools/clone.py --missing`）：建议做的事落在没克隆的项目上，就在那件事下写明「本设备没有克隆，建议放 <路径>，说「克隆 xx」」，并写进「需要你确认」
- **GTD 超期**（`python tools/inventory.py --gtd` 提示上个周日没做事情盘点）：把「发起 GTD 事情盘点」列为 **T1**，并写进结论
- **固定日程**（`python tools/schedule.py --json`）：`today` 里的事写进今日事项，按时间排（写「10:30 示例读书会」这种时段占用）；`reminders` 是今天该提前提的（默认提前 1 天，表里写「提前 N 天」按 N 算，「不提醒」的不会出现）——`date` 是明天的写进今日事项或「需要你确认」，更远的在结论里带一句；`error` 不为空时原样写进「需要你确认」（表在 `areas/work/index.md`），不要猜
- **今天建议做的事**：3–6 件，不要贪多。优先级依次是：
  1. 今天到期或逾期
  2. 卡住别人、或别人在等的
  3. 推进长期目标、本周焦点
  4. 拖了很久的待确认事项
  5. 顺手能清掉的小事
- 每件写清为什么是今天、预计用时、谁来做（你、我、agent）
- **目标不明确的项目**：有提交或有待办、但档案里没有清楚目标或完成标准的（比如「当前状态」写着「待补充」），每个给一句建议目标（推断）和一个需要你回答的问题
- 只用记录里的事实。估计的用时、优先级、目标都标（建议）或（推断）

### 3. 写 `plans/daily/YYYY-MM-DD.md`
文件已存在且 `status: active`（你已确认过）→ **不覆盖**，只在末尾追加「补充」一节。否则按 [templates/daily-plan.md](../../../templates/daily-plan.md) 写（`status: draft`）。任务行格式见 [entries.md#计划任务](../../../templates/entries.md#计划任务)。
然后：在 journal 追加一条 `## 10:00 早间建议（自动）`（`#auto`，一行，链到文件；当天的 journal 已经有这条就不重复加）；按 `templates/session.md` 写会话记忆（`kind: 自动`，`topics: [auto, morning]`，`importance: 1`）；`python tools/build_index.py`；`git add -A && git commit -m "docs: 早间建议 <日期>（自动）"`。

**禁止**：push 和任何对外发送；改 registry 和设备登记；碰 `private/`；改计划任务的状态；派发任务。

## B. 确认（交互）
你开始当天的会话、或者问「今天做什么」时：
1. 读 `plans/daily/<今天>.md`。**没有就派发，不在当前会话里自己生成**：在后台运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/agent-run.ps1 -Job morning`（和定时任务同一条路径，独立的无头 session 读 skill、读数据、写文件），跑完后只读它生成的文件。这样主会话不用把全部项目数据读进上下文
2. 先扫一遍「暂停与等外部」一栏和 `python tools/board.py` 的结果：复查日期到了 / 过期的按 [report-cards](../report-cards/SKILL.md) 出卡片问你（接手还是改日期），缺复查日期的当场补齐，不在三栏的补进对应栏——补完再往下走
3. 今天有固定日程、或今天是提前提醒日的（`python tools/schedule.py`），结论里先带一句（「今天 10:30 读书会」「明天有读书会」），今天有日程的排进建议事项；紧接着给结论，再把文件里「需要你确认」的事按 [report-cards](../report-cards/SKILL.md) 一件一张卡片（最多 5 张，挑最卡别人的，其余在表格后一行带过；带链接的先核对能打开），然后用表格列出建议事项（项目、事项、为什么今天、预计、谁来做），问你要保留、去掉、新增哪些，顺序怎么排
4. 按回复修改文件：去掉的写进「未选」一节并注明原因（以后再说的放进 `plans/someday.md`）；新增的补上；按执行顺序重新编号；`status: active`
5. **执行说明**（执行不在助手工作区做，CLAUDE.md §2）：给每个落在具体项目上、要动手做的任务，在任务下加一条「执行」，格式见 [entries.md#执行说明](../../../templates/entries.md#执行说明)：本设备路径（`python tools/device.py show`）、可选的带名字启动命令、开场直接粘贴的说明（目标、背景、验收、约束、做完怎么回报）。回复里只列任务和路径，说明留在文件里，需要时再看
6. 需要拆解的事项按 `plan` skill 建计划；属于已有计划的，在那个计划里同步
7. 「目标不明确的项目」得到回答的，更新项目档案的「当前状态」和 `plans/goals.md`
8. journal 记一条「确认今日事项」；更新会话记忆；提交
9. 晚上的 `daily-update` 会对照这份清单打勾，没完成的问一句要不要顺延
